= RP2040 PIO: instruction encoding
:toc: left
:toclevels: 2
:sectnums:

RP2040 PIO, ISA version 1.0.0. Generated from `pioscope/packs/pio/isa.yaml` by `pioscope isa-docs`; do not edit.

Diagrams show the most significant bit on the left. Under each box: the fixed value in binary, or the slot width in bits. `-` slots are reserved and must be 0; a `!` marks a field whose contents do not fit. The WaveDrom figures render with asciidoctor-diagram or a Kroki server.

== Word format

Every instruction is one 16-bit word made of fixed fields. Each instruction packs its operands into these fields, MSB first.

....
  15    13    12    8      7    0
+----------+------------+---------+
|  opcode  | delay_side | operand |
+----------+------------+---------+
     3           5           8
....

[wavedrom, target=enc-word, format=svg]
....
{reg: [{"bits": 8, "name": "operand", "type": 4}, {"bits": 5, "name": "delay_side", "type": 3}, {"bits": 3, "name": "opcode", "type": 2}], config: {"bits": 16, "lanes": 1, "hspace": 900}}
....

[cols="1,1,1,5",options="header"]
|===
| Field | Bits | Width | Role
| `opcode` | 15:13 | 3 | the major opcode (`push` and `pull` share 4, told apart by bit 7; `nop` is `mov y, y`)
| `delay_side` | 12:8 | 5 | side-set bits (MSB first, under an enable bit with `.side_set n opt`), then the `[n]` delay in the bits left
| `operand` | 7:0 | 8 | the instruction's arguments
|===

== Encoding pressure

Bits each instruction uses in each field (structural fields at full width). *Bold* = field exactly full; `!` = overflow.

|===

| `jmp` | 3 | 5 | *8*
| `wait` | 3 | 5 | *8*
| `in` | 3 | 5 | *8*
| `out` | 3 | 5 | *8*

== Instructions

[[instr-jmp]]
=== `jmp`

Syntax: `+jmp [cond], target+` +
Opcode 0 · status stable · modifiers: delay, side

If cond is true, set the PC to target; otherwise continue. x--/y-- decrement the register even when the jump is not taken.

....
  15    13    12    8     7    5   4    0
+----------+------------+--------+--------+
|  opcode  | delay/side |  cond  | target |
+----------+------------+--------+--------+
    000          5          3        5
....

....
{reg: [{"bits": 5, "name": "target", "type": 4}, {"bits": 3, "name": "cond", "type": 4}, {"bits": 5, "name": "delay/side", "type": 3}, {"bits": 3, "name": "opcode", "type": 2, "attr": "000"}], config: {"bits": 16, "lanes": 1, "hspace": 900}}
....

[cols="2,1,1,6",options="header"]
|===
| Slot | Bits | Width | Encoding
| `+opcode+` | 15:13 | 3 | opcode 0 (see <<opcode-map>>)
| `+delay/side+` | 12:8 | 5 | side-set bits (MSB first, under an enable bit with `.side_set n opt`), then the `[n]` delay in the bits left; the split is set by the program's `.side_set`
| `+cond+` | 7:5 | 3 | condition code, see <<conditions>>
| `+target+` | 4:0 | 5 | instruction address 0..31 (label)
|===

Example, `i2c_write.pio:23` (program `i2c_write`): `jmp x-- bitloop side 1 [7]` -> `0x1f44`

|  opcode  | side.en | side |  delay  |  cond  | target |
+----------+---------+------+---------+--------+--------+
    000         1       1       111      010     00100
....

[[instr-wait]]
=== `wait`

Syntax: `+wait pol, src, idx, [rel]+` +
Opcode 1 · status stable · modifiers: delay, side

Stall until the source equals pol: gpio = absolute GPIO idx, pin = input pin idx (relative to the in base), irq = IRQ flag idx (0-7; rel adds the SM number modulo 4). A satisfied `wait 1 irq` clears the flag.

+----------+------------+-----+--------+--------+
|  opcode  | delay/side | pol |  src   |  idx   |
+----------+------------+-----+--------+--------+
    001          5         1      2        5
....

|  opcode  | delay/side | 1 | ifempty | mode |   -    |
+----------+------------+---+---------+------+--------+

[[instr-mov]]
=== `mov`

Syntax: `+mov dst, src+` +
Opcode 5 · status stable · modifiers: delay, side

....
  15    13    12    8     7    5   4    3    2    0
+----------+------------+--------+--------+---------+
|  opcode  | delay/side |  dst   | src.op | src.src |
+----------+------------+--------+--------+---------+
    101          5          3        2         3
....

== Code tables

[[conditions]]
=== Conditions

The condition code is 3 bits; conditions with an argument carry it in the following `cond.arg` bits.

[cols="1,2,2,5",options="header"]
|===
| Code | Condition | Argument | Meaning
| 0 | `+always+` |  | Always (no condition written).
| 1 | `+!x+` |  | X is zero.
| 2 | `+x--+` |  | X is non-zero before the decrement; X is decremented either way.
| 3 | `+!y+` |  | Y is zero.
| 4 | `+y--+` |  | Y is non-zero before the decrement; Y is decremented either way.
| 5 | `+x!=y+` |  | X differs from Y.
| 6 | `+pin+` |  | The SM's jump pin (`.sm_config jmp=`) is high.
| 7 | `+!osre+` |  | OSR is not empty: its shift count is below the pull threshold.
|===

== Notes

* *Overflow:* none, every instruction fits in 16 bits.
* *`operand` field is full* for: `jmp`, `wait`, `in`, `out`, `mov`, `irq`, `set`, `nop`.
* *Headroom* (bits left in the most tightly packed instruction): `operand` 0 of 8.
* *Opcodes:* 0 of 8 free.
* This is the RP2040 format, so it is fixed: words match pioasm (tests: pioscope/packs/pio/tests/test_encode.py).
* An instruction memory of 32 words is shared by the block's four state machines; `jmp` targets are 5-bit absolute addresses.
